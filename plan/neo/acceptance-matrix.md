# Neo Acceptance Matrix

Status: active review checklist.

Use this matrix during implementation reviews. A milestone is not done until its
behavior, tests, docs, and migration notes are represented here.

## Phase 1 — VoiceApp

| Capability | Acceptance Criteria | Evidence |
|---|---|---|
| Public import | `from easycat import VoiceApp` is lazy and does not import heavy provider SDKs. Top-level `VoiceApp` is the ONLY new symbol against the top-level cap, which is fully exhausted at 94/94, so this PR bumps the `tests/test_public_api.py` cap 94->95 AND lands the triple-lock in the same PR: add `VoiceApp` to `__all__`, to `LAZY_EXPORTS`, to `docs/public-api.md`, and to `PUBLIC_API_SNAPSHOT`. `CostBudget`/`LatencyBudget`/`VoiceServer`/`EvalRunner`/`EvalScenario`/`EvalTurn` are submodule exports (`easycat.budgets`/`easycat.server`/`easycat.evals`) and do NOT count against this cap. | Public API test asserts the cap is now 95 and that the snapshot includes `VoiceApp`; import-cost/lazy import test. |
| Local mode | `VoiceApp(agent=agent).session("local")` builds a local-session config and `run("local")` delegates to `run_session`. | Unit test with monkeypatched `create_session`/`run_session`. |
| Browser mode | `run("browser")` starts WebRTC config server with per-offer session factory. | Unit test with monkeypatched `run_webrtc_config_server`; WebRTC focused test. |
| WebSocket mode | `run("websocket")` starts WebSocket config server with per-client transport. | Unit test with monkeypatched `run_websocket_config_server`. |
| Static config safety | A static transport-bearing `EasyConfig` is NOT safely cloneable: `dataclasses.replace` shares the grouped `observability`/`audio_processing`/`session_policy` sub-configs BY REFERENCE, so mutating a replaced config flips the original. No `with_transport`/`replace_transport`/clone primitive exists in `config/`. Therefore per-connection modes (browser/websocket/twilio) MUST go through `config_factory`; a single static config may only be used for single-session `local` mode. | Concurrency unit test asserts that mutating a `dataclasses.replace`-cloned config's `observability.debug` ALSO flips the original (proving naive cloning does NOT isolate concurrent sessions), and that the per-connection path mandates `config_factory`. |
| Factory mode | `config_factory` is the ONLY safe per-connection mechanism. Canonical signature is the per-transport factory shape `Callable[[TransportT], EasyConfig]` (concrete `WebRTCTransport`/`WebSocketConnectionTransport`/`WebTransportConnectionTransport`/`TwilioConnectionTransport`); the abstract `ConnectionContext` type is deleted from the plan and never referenced. It receives the connection transport and is called once per session. | Unit test asserts the factory is invoked once per session with the concrete transport and that each session gets an isolated `EasyConfig` instance. |
| CLI default | `easycat serve` still defaults to browser mode. | CLI test. |
| CLI security | Non-loopback `easycat serve` still requires token. | CLI test. |
| Twilio mode | `run("twilio")` starts reusable Twilio helper or raises clear optional-extra error. | Telephony fake tests. |
| Docs | README, browser playground docs, examples, and public API docs show `VoiceApp`. | Docs tests / markdown guard. |

## Phase 2 — VoiceServer

| Capability | Acceptance Criteria | Evidence |
|---|---|---|
| Server skeleton | `VoiceServer.from_app(VoiceApp(...))` starts and stops without leaking sessions. Capacity/draining/active-set state is NET-NEW at the shared VoiceServer layer: it is LIFTED out of the per-transport serve helpers (`webrtc.py:354,356-357,377-390,422-434,475-482`; `websocket.py:146,154-156,177-179`), NOT inherited from `SessionManager`, which is a bare add/remove/stop_all registry (`session_manager.py:18-105`) with no `max_sessions`, no `__len__`, and no draining state. `VoiceServer` mounts apps via their `config_factory` ONLY and never calls `VoiceApp.run()`. | `tests/server/test_voice_server_lifecycle.py` asserts no session leak and that the shared layer (not `SessionManager`) owns the active-set/semaphore. |
| Health live | `/health/live` returns 200 while process can respond. | Aiohttp route test. |
| Health ready (M4 scope) | `/health/ready` returns 200 when serving and 503 while draining/at capacity. M4 owns ONLY the serving/draining/capacity/route-ready signals; the manifest-loaded and plan-no-blocking-errors signals are DEFERRED to M6b. | Health route tests covering serving/draining/capacity/route-ready only. |
| Health ready (M6b scope) | `/health/ready` additionally fails (503) when the manifest is not loaded or the provider plan reports blocking errors. These M6b-owned readiness checks are gated behind the planner-parity test below passing. | Health route tests covering manifest-loaded + plan-no-blocking-errors signals. |
| Planner parity (REQUIRED gate, M6b) | The planner verdict matches the `create_session` outcome for every one of the 7 roles (stt/tts/vad/transport/agent/noise_reducer/echo_canceller): a role the planner reports as resolvable actually constructs, and a role it reports as blocked actually fails `create_session`. Reuse is catalog-only for stt/tts; vad/transport/agent/noise/echo use NET-NEW declarative metadata, so divergence surface is large and this test is mandatory. The manifest/plan readiness checks (above) MUST NOT ship until this test passes. | Parity test enumerating all 7 roles and asserting planner verdict == `create_session` outcome. |
| Auth | Bearer token accepted; missing/invalid token rejected; query-token compatibility only when enabled. The shipped env var name is `EASYCAT_SERVE_TOKEN` (not `EASYCAT_SERVER_TOKEN`). | Auth tests. |
| Non-loopback auth guard | The non-loopback-requires-token guard is a property of the unified `VoiceServer`/`AuthPolicy` layer applied to BOTH WebSocket and WebRTC transports. A non-loopback bind (e.g. `0.0.0.0`) with NO token and WITHOUT the explicit `AuthPolicy.unsafe_allow_no_auth=True` escape hatch RAISES at startup. This CLOSES a real unauthenticated `0.0.0.0` voice endpoint on the WebSocket path (`websocket.py:84,93,100-111` has no loopback gate today; WebRTC already enforces it at `webrtc.py:347-351,924-927`); it is not parity preservation. `unsafe_allow_no_auth` is a structured `AuthPolicy` field (default `False`), not prose-only. | Server bind/auth test asserts a non-loopback WebSocket bind with no token and without `unsafe_allow_no_auth` raises, and that setting `unsafe_allow_no_auth=True` allows it. |
| Query-token break note | `allow_query_token` defaults to `False`. `?token=` is UNCONDITIONAL today whenever a token is set (`webrtc.py:826-834`, `websocket.py:102-111`), so `allow_query_token=False` is a BREAKING CHANGE for the bundled WebSocket browser client (`examples/ws_browser_client.html:91-93` — browsers cannot set headers on the WS handshake). The bundled WebRTC client is UNAFFECTED (it sends `Authorization: Bearer`). A `allow_query_token=True` loopback opt-in is provided; the new default applies to the existing handlers too. | Auth test asserts query-token rejected by default and accepted only under the loopback opt-in. |
| Secret hygiene | Tokens do not appear in JSON diagnostics or metrics labels. | Auth/metrics tests. |
| Capacity | New sessions are rejected after max active sessions. The `Semaphore`/active-set that enforces this is net-new at the shared layer (lifted from the serve helpers, not added to `SessionManager`). | Capacity test against the shared VoiceServer internals. |
| Graceful shutdown | Server stops accepting new sessions, drains active sessions, then escalates after timeout. Draining state lives in shared VoiceServer internals; the test must NOT assume `SessionManager` owns draining (it is a bare registry). | Shutdown test with fake sessions asserting the shared layer drives drain->escalate, with `SessionManager` used only as the add/remove/stop_all registry. |
| Manifest loading | `easycat.toml` discovered, parsed, resolved relative to manifest dir, and converted to `EasyConfig`. NO loader exists today (no `bearer-env`/`tomllib`/`ProjectManifest` in tree) — this is net-new. | Project loader tests. |
| Manifest secret rule | `auth`/`token` fields MUST match the env-reference grammar `bearer-env:NAME` (NAME is a user-chosen env var identifier; `bearer-env:EASYCAT_SERVE_TOKEN` is the canonical example). The loader RAISES a coded error (`EASYCAT_Exxx`) when it sees a literal-looking secret (reuse `redaction._SECRET_RE`/`contains_unredacted_sensitive_text`). Any echoed/dumped manifest routes through `redact_value`. | Loader tests: (a) a literal-looking secret in `auth`/`token` is rejected with the coded error; (b) the `--json`/`/manifest` dump shows NO resolved token value (only the env reference). |
| Provider plan | Missing env/extras reported without provider instantiation. STT/TTS reuse `ProviderCatalog` metadata; vad/transport/agent/noise_reducer/echo_canceller use NET-NEW declarative metadata (no static catalog exists for those 5 roles). | Planner tests. |
| CLI plan | `easycat plan --json` emits provider plan envelope (`schema_version=1`). The envelope is covered by `tests/cli/test_json_schema.py`. | CLI JSON test in `tests/cli/test_json_schema.py`. |
| WebRTC route | `VoiceServer` can serve browser WebRTC without breaking old helper APIs. | WebRTC integration tests. |
| Metrics registration | The new `easycat.server.*` metric names are registered in `METRIC_DEFINITIONS` and the new labels `easycat.server_state`/`easycat.auth_result`/`easycat.route` are registered in `LOW_CARDINALITY_ATTRIBUTE_KEYS` in `_observability.py` IN THE SAME PR that emits them, because `_record_metric`/`sanitize_attributes` raise `ValueError` on any unregistered name/key (`:199,209-210`). `easycat.transport` is ALREADY registered (`:59`) and is not re-added. | Metrics test asserts the server emits through `sanitize_attributes` with no `ValueError` (registered names/labels). |
| Metrics route safety | `easycat.route` is constrained to an ENUMERATED set of route TEMPLATES; the value is asserted to be in the template set BEFORE recording, so a raw path with user content can never be emitted as a label. | Metrics test asserts an off-template route value is rejected before recording. |
| `/metrics` endpoint | `GET /metrics` returns 200 and the documented JSON shape. | Aiohttp route + JSON shape test. |
| `/manifest` endpoint | `GET /manifest` returns 200 and the documented JSON shape with NO resolved token values (routed through `redact_value`). | Aiohttp route + JSON shape test. |
| `/plan` endpoint | `GET /plan` returns 200 and the provider-plan JSON shape. | Aiohttp route + JSON shape test. |
| `/capabilities` endpoint | `GET /capabilities` returns 200 and the documented JSON shape. | Aiohttp route + JSON shape test. |
| Secret hygiene (metrics) | Tokens do not appear in JSON diagnostics or metrics labels. | Auth/metrics tests. |
| Docs | Deployment, Docker, observability, and README docs explain `VoiceServer` and manifest. | Guard docs. |

## Global Acceptance Criteria

- New public APIs are documented and covered by public API tests.
- New CLIs support `--json` when they emit structured output.
- Optional dependencies remain optional and fail with actionable messages.
- No secrets or PII are introduced into metrics labels or unredacted planning output.
- Existing lower-level APIs remain available until a deliberate next-major
  removal/deprecation pass.
- Generated docs route files are regenerated when route maps change.
