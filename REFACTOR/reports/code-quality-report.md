## 2. Bugs to fix now

### High severity

**#1 — OpenAI Agents tool-result `call_id` is always empty (`_openai_agents_events.py:63`).**
`map_run_item` handles `tool_call_output_item` with `raw = getattr(item, "raw_item", None); call_id = getattr(raw, "call_id", "")`. In the installed SDK (0.17.5), `ToolCallOutputItem.raw_item` is a `FunctionCallOutput` **dict** at runtime (`ItemHelpers.tool_call_output_item` returns a literal `{"call_id":…, "output":…, "type":"function_call_output"}`), so `getattr` on a dict returns `""` every time. The `tool_call_item` branch stores the *real* call_id as the pending-dict key (its `raw_item` is a pydantic model), so `pending.pop(call_id)` never matches. Three consequences: the barge-in drain condition `if not pending_tool_calls: break` (`openai_agents.py:197`) can never fire — after a barge-in during any tool-using turn the bridge consumes the entire remaining run; every `tool_result` event ships with `call_id=""` so start/result can't be paired; and the journal records an empty tool name. The two existing tests mask this by using attribute-bearing fakes (`SimpleNamespace(call_id=…)`, `type("Raw",(),{"call_id":…})()`).
*Fix:* mirror the SDK's own `ToolCallOutputItem.call_id` accessor — `getattr(item, "call_id", None) or (raw.get("call_id") or raw.get("id") if isinstance(raw, dict) else getattr(raw,"call_id","")) or ""`. Add a regression test whose `raw_item` is a plain dict matching `FunctionCallOutput`, asserting the result event carries the real id and `pending` empties.

**#2 — OpenAIAgentsBridge never cancels the streamed run on barge-in (`openai_agents.py:205`).**
On cancel-token cancellation `invoke()` just `break`s out of `result.stream_events()` and never calls `result.cancel()`. `Runner.run_streamed` executes the agent loop in a background task; abandoning the generator doesn't stop it, and when the generator is GC-finalized the SDK's `finally` takes the non-cancelled path and *awaits `run_loop_task` to completion* — so the interrupted run always finishes: remaining tool side-effects fire after the user cut the bot off, tokens are billed, and the `finally` snapshots `to_input_list()`/`last_response_id` from a still-mutating run, feeding `apply_interruption` and next-turn `previous_response_id` nondeterministic state. The primary barge-in path is cooperative (`CancelToken.cancel()`, not task cancellation), so the SDK's cancel-on-`CancelledError` arm never fires. `LlamaAgentsBridge` (`llama_agents.py:470-496`) already does this correctly and names the exact hazard.
*Fix:* in the cancel branch call `result.cancel()` before breaking — `mode="after_turn"` when `pending_tool_calls` exist (drain in-flight tools), else `"immediate"` — add a `GeneratorExit`/`CancelledError` arm mirroring Llama, keep consuming `stream_events()` as the SDK requires, and capture `to_input_list()`/`last_response_id` only after cancellation settles. The dead `interrupted` flag (#24) is the visible residue of this dropped guard.

### Medium severity

**#3 — Push-to-talk press during PROCESSING is silently dropped (`turn_manager.py:603`).**
`start_turn()` (the PTT public API) guards `if self._state not in (IDLE, BOT_SPEAKING): return`, so a press during PROCESSING is a no-op: no new turn, no cancel of the stale agent run, and the user's speech survives only in the ~300 ms pre-roll. VAD mode treats the same situation as barge-in (`turn_manager.py:384-388 → _handle_barge_in`), and the shipped `push_to_talk` toggle desyncs because it flips its `speaking` flag while the manager no-ops. PROCESSING is exactly the window (agent latency) where a PTT user most wants to retract, and there's no VAD to rescue them.
*Fix:* before the guard, add `if self._state == TurnManagerState.PROCESSING: await self._handle_barge_in(); return` (arguably `USER_PAUSED` too), cancelling the stale token and starting a fresh USER_SPEAKING turn. Add a PTT test for a press during PROCESSING.

**#5 — Libsql sync thread bypasses the single-writer lock (`journal_sql.py:1018`).**
The SQL journal family's discipline is "single-writer via `threading.Lock`" and `LibsqlJournal._do_append` serializes all connection access under `self._lock` (978). But `_sync_loop` calls `self._conn.sync()` every 10 s with **no lock** (1020) on a daemon thread that only exists when a remote `sync_url` is configured — the whole point of the backend. `flush()`/`finalize()` also touch the connection unlocked. So the session thread (mid-append, commit pending) and the sync thread operate on one libsql connection concurrently. Because `append()` treats any `_do_append` exception as fatal (`_enter_degraded` → returns `-1` forever), a race-induced error permanently drops every subsequent record for the session — and observability is the single source of truth. (The one unverifiable link is whether `libsql_experimental.sync()` releases the GIL; either way it violates the class's own stated discipline.)
*Fix:* acquire `self._lock` around `conn.sync()` in `_sync_loop`, `flush()`, and `finalize()` (sync is short vs the 10 s interval), or move syncing onto the append thread/queue. Add a regression test with a `sync_url` appending concurrently with sync ticks.

**#7 — Validation quick/socket/stress/contracts lane skips exact secret redaction (`validation/runner.py:196`).**
`run_validation_slice` computes `runtime_secret_values` at line 190 but applies them only to `junit.xml`; `stdout.log`/`stderr.log` get pattern-only `redact_text()` (196-197) and the `ValidationFailure.message` is raw pytest output with no exact-secret pass (250). The pattern regex only matches `sk-/sess-/key-/tok-` prefixes, so a plain-hex `DEEPGRAM_API_KEY` a failing test echoes lands verbatim in shared/uploadable artifacts and `failures[].message`. Every *other* lane (`run_latency/live/release_validation`) applies `redact_runtime_secrets` to stdout/stderr and pre-redacts the message; this lane computing the secrets but wiring them into only the junit write is the tell that it's an oversight. `run_release_validation` invokes this slice (1109), so release inherits the gap.
*Fix:* change 196-197 to `redact_runtime_secrets(result.stdout/stderr, runtime_secret_values)` and wrap the failure message at 250 — matching the three sibling lanes exactly.

**#4 — `tail`/`journal follow` retry restarts from the original sequence (`cli/debug/bundles.py:2388`).**
`_runner` wraps `_stream_follow` in `while True` and on `FileNotFoundError`/`sqlite3.OperationalError` re-calls it with the *original* `from_sequence`. `JournalView.follow` keeps its cursor in generator-local state, and `ReadonlySqliteJournal.read` opens a fresh RO connection per poll against a file a live session is writing — so a "database is locked" error can fire mid-stream. On restart, `--from-sequence 0` re-emits every already-printed record; default `None` resumes at `latest_sequence+1` computed at retry time, silently skipping records written during the outage with no `follow_gap` notice. (WAL with `wal_autocheckpoint=0` makes the trigger narrow but real.)
*Fix:* have `_stream_follow` track the highest yielded `record.sequence` and resume the retry from `last_seq+1`, keeping the original `from_sequence` only for the first attempt (before any record streamed).

**#3-config — `enable_echo_cancellation` silently ignored (`config/easy.py:827`).**
The flag is documented as "force AEC on/off," but its only reader is `_default_echo_cancellation_for_transport`, called *only* when `self.echo_cancellation is None`. `create_session` then derives the pipeline flag purely from `EchoCancellationConfig.enabled` (`_factory.py:404-408`), which defaults to `False` → `PassthroughAEC`. So `EasyConfig.browser(echo_cancellation=EchoCancellationConfig(fallback_policy="error"))` — a preset that promises AEC on and sets the flag — silently runs with AEC off, and the `fallback_policy="error"` hard-fail never fires. Reproduced at runtime.
*Fix:* in `__post_init__`, when `enable_echo_cancellation is not None` and `echo_cancellation` is a config object, `replace(cfg, enabled=flag)`; warn/raise on a pre-built `EchoCanceller` conflict. Add a regression test on `EasyConfig.browser(...).echo_cancellation.enabled`.

**#11 — `aclose()` not propagated down the agent generator chain (`_agent_runner.py:199`).**
The barge-in path closes only the top stream; neither `AgentStage.execute_streaming` (its `finally` never `aclose`s the wrapped `bridge.invoke(...)`) nor `AgentRunner.invoke`'s bridge loop (no `try/finally` closing `inner_iter`; only the timeout branch closes it) forwards the close. When `GeneratorExit` hits their yields, the inner bridge is suspended and finalized only by the asyncgen GC hook — one loop tick per layer. Each bridge's `BaseException` arm carries correctness-critical, ordering-sensitive work: LangChain/LangGraph persist the *partial* turn so a follow-up `apply_interruption` truncates *this* turn's assistant message rather than rewriting the previous turn's. In the narrow window where the consumer stops pulling on a post-cancel event before the bridge re-checks cooperative cancel, `apply_interruption` runs first and rewrites the prior turn's message — intermittent, journal-visible next-turn corruption. `llama_agents.py:182-194` already propagates `aclose` for one layer with a comment on this exact failure mode.
*Fix:* wrap the consumption loops in both `AgentStage.execute_streaming` and `AgentRunner.invoke` in `try/finally` that awaits `stream.aclose()`/`inner_iter.aclose()` (generalizing the timeout-only aclose). No-op on normal completion. Add a regression test driving AgentStage→AgentRunner→LangChainBridge where the consumer breaks on the first post-cancel delta.

**#12 — ElevenLabs batch STT has zero retry (`stt/elevenlabs_provider.py:555`).**
`OpenAISTT` retries its batch POST on 429/`TransportError`/`TimeoutException` with backoff (`openai_provider.py:168-196`); `ElevenLabsSTT._transcribe_batch` does a single unretried `client.post` + `raise_for_status`, and `ElevenLabsSTTConfig` has no `max_retries` field. On the mid-stream cap path (`_buffer_batch_audio_or_finalize` → finalize), a transient 429 propagates out of `send_audio` into the per-chunk pipeline error policy the finalize mechanism exists to avoid, and the same recording would have survived through OpenAI. (The finding's "buffer cleared first is worse" framing is not load-bearing — OpenAI clears before awaiting too; the sole defect is the missing retry.)
*Fix:* hoist the bounded retry loop into a shared `stt/base.py` helper and have `_transcribe_batch` call it; add `max_retries: int = 3` (with `>=0` validation) to `ElevenLabsSTTConfig`.

**#13 — Crash-dump promotion can crash journal startup (`journal_sql.py:319`).**
`_promote_crash_dump` is best-effort (its `except OSError` degrades instead of failing `__init__`), but two escapes break that: `mkdir_private(crash_dir)` at 319 runs *before* the `try` (326), so an `OSError` (full/read-only FS, or `crash-dumps` existing as a file) propagates out of `SqliteJournal.__init__`; and inside the `try`, `_copy_journal_to_crash_dump` only swallows `sqlite3.OperationalError`, so a `sqlite3.DatabaseError` from a malformed WAL (exactly the crash being recovered) escapes the `except OSError`. Either aborts `create_session`, so a bot can't restart after a crash — precisely when robust startup matters. The authors already wrap the *sweep* call in `except (OSError, sqlite3.DatabaseError)` and put `mkdir_private` inside its `try`.
*Fix:* move `mkdir_private` inside the `try`, broaden the handler to `except (OSError, sqlite3.Error)` routing to `_reopen_after_failed_crash_dump`. Add a test seeding an unclean same-id journal whose checkpoint raises `DatabaseError`.

**#14 — Outbound call manager silently skipped on blank Twilio creds (`_telephony_wiring.py:233`).**
`_build_outbound_helpers` wires the full outbound pipeline (classifier, voicemail detector, disposition tracker, state machine, IVR) but constructs `OutboundCallManager` only `if oc.twilio_account_sid and oc.twilio_auth_token:` with no `else` — no log, no error — swallowing the `ValueError` the constructor would raise. Both fields default to `""` with no env auto-load, so forgotten creds are the common misconfiguration. `create_session` succeeds, then the app fails much later with a `NoneType` `AttributeError` when it reaches for the manager. The `ImportError` branch one line below at least logs a warning; this contradicts the config layer's fail-fast for missing STT/TTS keys.
*Fix:* add the `else` warning at minimum; better, validate in `EasyConfig._validate`/`TelephonyConfig` and raise when the manager is enabled but a credential is blank.

### Low severity (bugs & functional error-handling)

- **#19 Twilio reconnect race (`twilio_media.py:627`).** `send_audio`/`send_mark` clear `self._ws` on `ConnectionClosed`, allowing a new connection to be accepted before the old handler's `finally` runs. Unlike `websocket.py:412-426` (guarded with `if self._ws is ws:` / `elif self._ws is None:`), the Twilio `finally` unconditionally nulls `_ws`, wipes `_stream_sid`, emits a spurious `CallEnded` (carrying the new call's sid, since `_handle_start` reset the flag), and enqueues the receive sentinel — killing the freshly reconnected call. Near-unreachable in single-threaded asyncio but a genuine latent gap; same pattern at `1048-1068`. *Fix:* copy the WebSocket guard.
- **#18 Transport `clear_audio` Protocol contradiction (`providers.py:296`).** `clear_audio` is declared in the `runtime_checkable` Protocol body yet its docstring says it's optional, and the same file states optional capabilities are kept *out* of the body precisely to avoid `isinstance` rejection. Reproduced: a transport omitting `clear_audio` fails `isinstance(x, Transport)`. The shipped contract kit is self-contradictory — `contracts.py:329` asserts the isinstance while `contracts.py:349-353` skips when `clear_audio` is absent. *Fix:* move `clear_audio` into the optional-capabilities comment block (runtime already discovers it via `getattr`).
- **#20 InMemoryArtifactStore eviction ignores ref-counts (`artifacts.py:144`).** The default `debug="light"` pairing is `InMemoryRingBuffer` (ref-counted) + `InMemoryArtifactStore` (50 MB). The store's `_evict_if_needed` pops by insertion order with no knowledge of ref-counts, deleting blobs whose records are still buffered → bundles/replay with dangling `input_ref`/`output_ref` and no overflow signal. `FilesystemArtifactStore` refuses new writes for this exact reason. Ephemeral data, degraded-replay symptom only. *Fix:* mirror the filesystem policy (refuse-new-at-cap + log once), or share the ring buffer's `_ref_counts`.
- **#21 SileroVAD rate-change misframing (`silero.py:210`).** `_buffer` accumulates sub-frame remainders but `target_rate`/`frame_bytes` are recomputed per call; a mid-stream 8k↔16k switch concatenates old-rate leftover bytes with new-rate bytes and slices at the new frame size → one garbled frame. Reachable only via custom transports that renegotiate rate. Bounded to a single boundary frame (finding's "silently degrades detection" overstates it). *Fix:* track `_buffer_rate`; discard the stale remainder on change (don't raise — VAD is continuous).
- **#22 Env-flag truthiness drift (`config/_factory.py:611`).** `EASYCAT_DEV` is gated on bare `os.getenv` (so `"0"`/`"false"` are truthy) while `easycat serve`/`dev.py` use the canonical set-parser (those values are falsy); `EASYCAT_EMERGENCY_EXPORT` arms only on exactly `"1"`, rejecting `"true"`/`"yes"` that sibling flags accept. `EASYCAT_DEV=0 easycat serve` still imports the 3006-line debugger module (arm re-checks correctly, so no wrong session, just import cost); `EASYCAT_EMERGENCY_EXPORT=true` silently never arms. *Fix:* hoist `is_truthy` into a shared `easycat/_env.py` and use it at both sites.
- **#32 close()/destroy() guard misses the stopping window (`_session.py:1224`).** `stop()` flips `_is_running=False` before ~10 awaits of teardown, during which `_stopping` is True; both guards check only `_is_running`, so a concurrent `close()`/`destroy()` passes and can write the clean-close marker early or swap in a read-only journal that silently drops the teardown tail. Requires a second task calling a deprecated alias mid-stop. *Fix:* `if self._is_running or self._stopping:` (finally resets `_stopping`, so legit post-stop calls still pass).
- **#33 Terminal WS STT death → clean empty transcript (`stt/websocket_base.py:159`).** All WS STT providers install a no-op reconnect hook, so `recv_iter` returns (never raises) on terminal drop; `_receive_loop`'s `finally` queues the None sentinel, `events()` ends cleanly, and the committer's `resolve_pending(turn, "")` hands the turn an empty transcript with no Error emitted. The TTS side was explicitly hardened against this downgrade (`_multi_context_ws.py:358-373`); STT has no equivalent. On the common partition path `ReconnectFailure` *is* journaled (only the budget-exhausted path is silent), so it's graceful degradation, not total blindness. *Fix:* expose a died-abnormally signal from `ReconnectingWebSocket` and `_emit_provider_error` before the sentinel.
- **#34 Recoverable WebRTC negotiation failure marked fatal (`webrtc.py:1360`).** A failed `/offer` returns 400 with the transport fully alive, yet emits `TransportDegraded(fatal=True)`. Fatal events are exempt from the 1 s coalescing *and* the 64-task cap and are journaled as CONTROL, so a client looping junk SDP floods the journal with "fatal" records for a healthy server, masking real fatal events. Sibling emitters and webtransport pair fatal with `close_connection`. *Fix:* emit `fatal=False`.
- **#35 `bundles export --force` rmtrees arbitrary dirs (`cli/debug/bundles.py:558`).** `_prepare_output_dir` guards only the FS root and cwd, then `shutil.rmtree`s any other existing `--output` dir. `export run.zip -o .. --force` resolves to cwd's parent (neither root nor cwd) and deletes the parent tree including cwd. Requires explicit `--force` + unusual `-o`. (The finding's "inconsistent with `journal promote`" framing is a misread — that command's output is a *file*.) *Fix:* refuse dirs lacking a pack marker, or reject ancestors of cwd / `Path.home()`.
- **#36 `diff --turn <non-int>` silently empty (`cli/debug/bundles.py:1604`).** `int(turn)` failure sets `wanted=None`, filtering out every turn; the command exits 0 with `turns=[]` and prints "No aligned turns to diff." A user typing a turn-*id* (which `replay` accepts) concludes the runs had no comparable turns. `replay --turn` validates up front and exits 2. *Fix:* emit `emit_command_error(..., exit_code=2)` on non-integer.
- **#37 STT `end_stream()` failure swallowed silently (`_stt_committer.py:414`).** Bare `except Exception: pass` with no logging, unlike the codebase norm (`logger.debug(..., exc_info=True)`) used everywhere else including two other spots in this same file. Cancel-path only, so observability loss only. *Fix:* `logger.debug("STT end_stream during cancel raised", exc_info=True)`.

## 3. Duplication & architecture

The recurring theme: shared abstractions **already exist** (`stages/base.py`, `BridgeTemplate`, `ServerTransportBase`/`AudioQueueMixin`, `_journal_codec.py`, `run_interruption_journal_protocol`) but copies were made alongside them and have started to drift. Consolidation aligns with existing conventions rather than fighting protocol-over-inheritance or one-provider-per-file. All items below are incrementally landable.

**#8 — WebRTC signaling duplicated across transport and routes (`server/webrtc_routes.py:500` vs `transports/webrtc.py`).** *Medium.* `WebRTCRoutes` carries near-verbatim (docstrings literally say "byte-identical to the transport") copies of security-relevant stateless logic: `_cors_headers` (901-921 / 299-324), `_stats_quota_error` (1004-1029 / 573-599), forbidden/quota responses (979-1002 / 550-571), `_ice_servers_as_dicts` (875-892 / 470-481), the stats-persist flow, and the `handle_root` `?webrtc=` sanitizer (1503-1545 / 617-664). Two surfaces (standalone transport vs VoiceServer-mounted routes) mean a hardening fix can land in one copy — and `_stats_write_permitted` has *already* diverged. Auth is only two-way, not triple (routes already delegate to the unified `AuthPolicy`). *Shared abstraction:* lift the config-only helpers into `server/_webrtc_shared.py` (matching the already-shared `_sanitize_webrtc_base`/`_is_loopback_host` pattern) and have both call them; route `WebRTCTransport._request_authorized` through `server.auth.BearerTokenAuth`. ## 4. Smells & cleanups

- **#39 Pure-Python mulaw codec (`twilio_media.py:864`).** Per-sample encode/decode loops burn measurable event-loop CPU (benchmarked ~5–15 ms per second of audio) on the most latency-sensitive path; at `max_sessions=64` the aggregate is significant. G.711 is trivially table-driven (256-entry decode LUT, segment/exponent encode table) — pure stdlib, orders of magnitude faster.
- **#40 `/stats` sync file I/O (`webrtc.py:1484`).** Every POST `stat()`s + re-reads the whole JSONL artifact for the record-count quota, then does a sync `mkdir`+`open`+`write`, on the loop, up to 120/min. Gated behind `stats_path` (inactive in normal prod). *Fix:* in-memory record counter (the process already tracks `_stats_request_times`) + `asyncio.to_thread` the append; apply to the duplicated routes copy.
- **#41 Twilio media listener omits `compression=None` (`telephony/server.py:224`).** Every other realtime WS `serve` call explicitly disables permessage-deflate; this one (and the scaffold template) doesn't, so the library negotiates deflate on per-20 ms mulaw frames if a client offers it. Trivial one-liner to match the other three listeners.
- **#42 ElevenLabs realtime final-timeout stale (`stt/elevenlabs_provider.py:33`).** Hardcoded `5.0` with a "Mirrors OpenAIRealtimeSTT" comment — but the sibling was tuned to `0.9` and promoted to a config field precisely because the wait shows up as user-visible dead air. On a provider stall this adds ~5 s of turn-to-agent latency and isn't operator-tunable. *Fix:* add `final_transcript_timeout_s` to the config; fix/drop the comment.
- **#43 `validate latency --json` envelope inconsistency (`cli/validate.py:508`).** `command` is `f"validate latency {mode}"` on success but `"validate latency"` on usage error — three values for one command, breaking `payload["command"] == "validate latency"` dispatch. Usage errors also route human text to stdout (unlike every other command's stderr default). *Fix:* constant `command`, carry mode as a field, drop the `human_console=stdout_console` overrides (updates 3 tests that pin current behavior).
- **#23 Dead `_closed` re-check (`_session.py:907`).** The inner `if self._closed: event.set()` is unreachable (no await between it and the early return; `_mark_closed` is sync/loop-bound). Misleads readers about the concurrency model. *Fix:* delete.
- **#25 Dead `ReplaySpec` `__getattr__` forwarder (`stages/base.py:169`).** Guards a "would deadlock" cycle that doesn't exist — `runtime/replay.py` never imports `easycat.stages`, and all 7 stage modules already top-level import `ReplaySpec` fine. Only two tests use the alias. *Fix:* delete the forwarder + false comment; point the tests at `easycat.runtime.replay`.
- **#24 Write-only `interrupted` flag (`openai_agents.py:184`).** Set but never read (`if not interrupted: interrupted = True` is a self-referential no-op); residue of the dropped chain-state guard live in the responses_api sibling. *Fix:* delete the flag. Do **not** port the responses_api guard without first verifying the Agents-SDK interruption contract — this bridge intentionally chains-then-annotates (see #2).

## Appendix — refuted findings (do not re-report)

1. **STTCommitter.commit_now finally clobbers a successor commit task** (`_stt_committer.py`) — Failure scenario unreachable: asyncio doesn't defer cancellation during I/O suspension; single-flight guard + `cancel_scheduled()`-first callers + provider `_lifecycle_lock`/`_COMMIT_MIN_BYTES` all independently prevent it.
2. **Telephony racy `Semaphore.locked()` capacity idiom** (`telephony/server.py`) — Applies threading-race logic to single-threaded asyncio; `locked()` is sync and the following `acquire()` never suspends when a slot is free, so no interleaving window exists.
3. **HTTP TTS cancel-race: `httpx.StreamClosed` escapes the `HTTPError` swallow** (`tts/openai_tts.py`) — Verified against httpx 0.28.1 + repro: mid-stream close raises `ReadError` (an `HTTPError`, already swallowed); `StreamClosed`'s top-of-`aiter_raw` check is passed once at start and never re-hit here.
4. **DeepgramTTS.stop() sends Flush then closes, dropping flushed audio** (`tts/deepgram_tts.py`) — No runtime path calls TTS `.stop()` mid-synthesis (teardown uses `cancel()`); only one docstring subclause is imprecise, method is never on a hot path.
5. **LangGraphBridge reads checkpointed state after cancel-break while run executes** (`langgraph.py`) — Cancel-detection branch + `get_state` are fully synchronous (no await), so the abandoned producer task can't run between break and read; no moving-target corruption.
6. **debugger `_make_app` 880-line closure makes handlers untestable** (`debugger/server.py`) — Every heavy/pure concern (DSP, regex analysis, filtering, AEC, WAV/zip) is *already* module-level and importable; the closure holds only thin HTTP wiring. Aesthetic, premise largely false.
7. **`play_hold_audio` fires a background task with no strong ref / no prior-cancel** (`_telephony_wiring.py`) — Task *is* stored in `self._hold_audio_task` (strong ref); `gate.close()` is single-flight per answer (state flips to CLASSIFYING before yielding), so no double-synthesis.
8. **Classification/max-duration timers reassign without cancelling** (`telephony/call_state.py`) — Sole caller `_on_answered` is state-guarded and transitions before starting timers, so double-start is unreachable; scenario is explicitly hypothetical.
9. **TTS synthesizer cancel() swallows all exceptions with no logging** (`_tts_synthesizer.py`) — Bare-pass is an established coexisting pattern (~26 sites incl. the sibling STT committer); cancel/teardown path, observability nicety only, no deviation from a norm.
10. **config ↔ transports import cycle masked by function-local import** (`config/_factory.py`) — No actual import-time cycle (`import easycat.config` loads clean); the deferred edge is a deliberate, documented PEP-562 layering convention and would fail-fast loudly if broken.
11. **Force-path teardown self-awaits the pipeline task and deadlocks** (`_session.py`) — Force branch `cancel()`s the task before awaiting it, so the self-await raises `CancelledError` immediately (swallowed), not a hang; reproduced. No internal path reaches the force branch from within the pipeline task.
12. **Teardown await loops swallow cancellation of stop() itself** (`_session.py`) — Intentional: every awaited task is pre-cancelled (near-immediate unblock), and running to completion is required by the documented teardown contract; repo cancels cooperatively via CancelToken, never `Task.cancel()` on lifecycle coroutines.
13. **STTCommitter finally re-check analogy / next-turn clobber** — (covered by #1 above; same reasoning class, unreachable window).
