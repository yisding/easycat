# EasyCat Improvement Plan

*Pre-launch. No back-compat constraints. Four goals: easiest to onboard, learn, maintain, extend.*

---

## 1. Where EasyCat already stands

EasyCat's foundations are unusually strong for a pre-launch framework, and the plan below deliberately builds on them rather than around them.

- **Onboarding** has one canonical 3-line shape (`run(EasyConfig.mic(agent=...))`) repeated byte-for-byte across README, the first example, and the `init` scaffold; near-zero forced decisions before first audio; and best-in-class error paths (`EASYCAT_E203` with fix text, `easycat explain`, a `doctor` preflight that actually catches missing keys/extras/mic before the user debugs the wrong layer).
- **Learnability** rests on a 16-chapter teaching ladder with real pedagogy (wrong-version-first chapters, ≤200 new lines per step, auto-generated diffs kept fresh by tests), a 40-example directory with a chooser matrix, and errors that teach.
- **Maintainability** is anchored by 4,514 deterministic tests (quick lane green in 3m41s), a closed-loop drift-guard system where doc command tables are parity-tested against canonical sources, an enforced flaky-quarantine policy with zero current quarantines, and a scannable `session/` decomposition (`_builder.py` is a linear, commented assembly — not indirection theater).
- **Extensibility**'s out-of-tree path is genuinely excellent: small, superbly documented Protocols in `providers.py`, direct instance injection into `EasyConfig`, runnable `custom_stt/tts/vad` examples, and a graceful agent ladder from `async run(text) -> str` up to a full `ExternalAgentBridge`.

The weaknesses are concentrated, not diffuse: a dead PyPI install path, a README that buries its hook at line 318, machine-agent boilerplate diluting every human doc, a ~15-touchpoint in-tree provider recipe whose metadata is scattered across five modules, no published reference layer for the production API, and a handful of 200–430-line streaming/bridge functions.

## 2. How the field does it

**Pipecat** wins adoption with a ruthlessly short golden path — `pipecat init` → keys → `uv run bot.py` → *talk to the bot in a bundled browser client* — plus a huge visible integration surface and an external `pipecat-{vendor}` community-package program. Its pain surface (invisible turn misfires, a hidden default that added ~1s latency, frame-abstraction footguns) is the inverse of EasyCat's journal-first strengths. **Takeaway: the first run must end in a conversation, and hidden latency defaults are reputation killers — both are where EasyCat can copy the win and dodge the wound.**

**LiveKit Agents** removes provisioning friction in layers: a terminal `console` mode that runs a full session locally with zero server setup, starter templates with auto-written `.env`, and a unified inference key so newcomers never sign up with five vendors. Its most-praised testing story is text-first agent evals shipped *inside* the starter template. **Takeaway: a zero-infrastructure console mode plus evals-in-the-scaffold is the strongest first-day-to-second-week DX ramp in the field.**

**The wider voice landscape** splits into hosted platforms that win on time-to-first-conversation and open frameworks that win on control but bleed users on setup. The differentiators named repeatedly: talk-to-it-in-10-minutes paths, browser testing before any telephony, layered test ladders, and per-stage latency attribution (the #1 cited production pain). **Takeaway: EasyCat's journal-first runtime is already aligned with where the market is heading — the gap is surfacing it: browser playground, latency waterfall, documented test ladder.**

**DX exemplars** (FastAPI, Stripe, Pydantic, Astral, Diátaxis adopters) converge on minimizing time-to-first-hello-world, making first success possible with zero keys, treating error messages as page one of the docs, progressive disclosure with escape hatches, and executing every doc snippet in CI. **Takeaway: EasyCat already has the bones (façade config, doctor, guarded docs); the missing pieces are the zero-key instant demo and a real reference/explanation layer.**

**Plugin/maintainability research** (pytest, Datasette, LangChain, Airflow, OpenTelemetry) yields one playbook: small stable core with Protocol contracts, third-party providers as separate pip packages via entry points layered on an in-tree registry, an *installable* contract-test kit so external authors subclass standard tests, and an explicit pre-1.0 stability statement. **Takeaway: EasyCat's registries and `tests/contracts` map almost one-to-one onto this playbook — the gaps are external discoverability and exporting the contract kit.**

## 3. Recommendations

Effort: S/M/L. Impact: H/M/L. Ordered within each pillar by impact-per-effort.

### Onboard

#### O1. Make the scaffold/app install path actually work pre-launch — *S / H*
**Why.** The only route that works today is repo-clone; `easycat` 404s on PyPI, so every generated scaffold's `uv sync` and the README's `uv add 'easycat[quickstart]'` dead-end with no hint why. The repo itself documents the gap (`test_scaffold_smoke.py`: round-trip "intentionally skipped").
**What.** In `cli/scaffold/init.py`, detect an editable/repo install (or accept `--easycat-source PATH` plus a matching field in the `--config` JSON schema) and render a `[tool.uv.sources] easycat = { path = ..., editable = true }` block into the generated `pyproject.toml` via an `$EASYCAT_SOURCES_BLOCK` template placeholder (empty once published). Fix the README line-39 "published package" framing and the generated template READMEs. Add a resolution-only smoke test (`uv lock` / `uv sync --dry-run` in a temp dir, offline-skip) to `test_scaffold_smoke.py` — not a full `uv sync`, which would drag numpy/onnxruntime into every guard run. At launch: publish, render the block empty, keep the smoke test.

#### O2. Restructure the README around the 3-line quickstart; add an explicit no-mic/no-key row — *M / H*
**Why.** The strongest hook a voice library has — 3 lines to a talking bot — sits at line 318 of a 934-line README, behind the extras catalog, a 75-line CLI section, and 100 lines of validation workflow.
**What.** Reorder: value prop → the existing quickstart snippet above the fold (move, don't rewrite — it's pinned by `test_quickstart_e2e.py`) → a 4-command install block standardized on the `.env` convention the scaffold already uses → an explicit "No mic or API key yet" row in Choose Your Path pointing at `examples/journal_demo.py` and teaching ch. 11–12 → links out. Move `## Validation Workflow` to a `docs/` page and retarget its docs route in `cli/_app.py`. Trim `easycat init`'s human "Next steps" from 13 lines to ~4 (keep the full catalog in the `--json` envelope). Update all guards in the same change — `test_quickstart_e2e.py`, `test_install_guidance.py`, `test_docs_index.py`, `test_init.py`, `test_markdown_links.py` — and verify with `guard-docs`, `guard-validation`, `guard-markdown`, `guard-templates`. The guard surface is what makes this M rather than S.

#### O3. Keyless console demo: `easycat console` — *M / H*
**Why.** Every competitor's winning first 60 seconds is talking to a bot with minimal provisioning; EasyCat's first run requires an OpenAI key and a mic, despite the repo already containing everything needed for a zero-account success.
**What.** New Typer command with a capability ladder: keyless default = interactive stdin loop over `create_text_session(agent=NoopAgent())` with `debug="light"` and `record_to=` (do **not** wire NoopSTT/NoopTTS — they emit nothing; text sessions are the real keyless path and still journal every turn); `--voice-demo` = `scripted_turn_providers()` through the full audio pipeline as `journal_demo.py` does; key + mic (via doctor's `check_microphone()`) = live voice; key, no mic = live text. Always end by printing the exported bundle path plus "Replay this session: `easycat replay <bundle>`" — the journal becomes the payoff of the first run. Register in `_COMMAND_TEXT` and the docs route map; document console as interactive-only (exempt from the `--json` envelope) in `explain json-schema`; add `tests/cli/test_console.py` driving the loop via piped stdin. Post-PyPI, `uvx --from 'easycat[quickstart]' easycat console` becomes the README's first runnable line.

#### O4. One polished browser playground (`easycat serve`) — *L / H*
**Why.** Pipecat's quickstart ends at localhost:7860; LiveKit productized its playground. EasyCat already ships a bundled WebRTC client (`transports/static/webrtc_client.html`, mic button, status, root redirect) — but no transcript, no interruption indicator, no latency readout, no single command to launch it, and the WS transport serves no HTML at all.
**What.** Upgrade the *existing* bundled client rather than building anew: (1) add a server→browser event channel (WebRTC data channel + matching JSON control messages in the WS wire protocol) carrying STTPartial/Final, TurnStarted/BotInterrupted, and per-turn latency; (2) extend the client with live transcript, interruption indicator, latency readout; (3) add `easycat serve` wiring `EasyConfig.browser()` + the client, printing "Open http://localhost:PORT", reusing the WS/docker token-and-loopback defaults; (4) promote the WS wire-format docstring to a maintained docs route; (5) link the debugger UI from the page; (6) extend `tests/transports/test_webrtc.py` and guard-examples with a served-page smoke. The genuinely new work is the event channel and CLI command — hence L, not XL.

### Learn

#### L1. Split human docs from machine docs: one-line pointer + generated `llms.txt` — *M / H*
**Why.** Near-identical "--json when a script or coding agent…" paragraphs open every human-facing doc — README, `docs/README.md`, teaching READMEs, examples README, CONTRIBUTING, `tests/contracts/README.md`, DURABILITY.md, and all six scaffold template READMEs — diluting the few commands a human needs. The machine audience is better served by a dedicated generated index.
**What.** Replace the boilerplate everywhere with one line ("Coding agent? Start at `llms.txt` or `uv run easycat explain json-schema`."). **In the same change**, flip the guard tests that pin the old phrases verbatim (`test_docs_index.py`, `test_contributing.py`, `test_examples.py`, `test_templates.py`, `test_ladder_index.py`) so five guard lanes stay green and now enforce the slimmer convention. Add `scripts/regen_llms_txt.py` (mirroring `regen_teaching_chapters.py`, with `--check`) generating `llms.txt` and `llms-full.txt` from the same source as `easycat docs --json`; add a `--check` guard test wired into `just guard-docs` plus the raw-fallback lists in CLAUDE.md/CONTRIBUTING.

#### L2. Per-turn latency waterfall in the CLI plus a "latency defaults" docs page — *M / H*
**Why.** Latency attribution is the #1 cited production pain, and Pipecat lost reputation to a single hidden default. EasyCat's journal already records the spans and the debugger already renders a waterfall — but the CLI doesn't expose it, and `TurnManagerConfig.end_of_turn_silence_ms = 1000` is exactly the kind of undocumented default that bites.
**What.** Two pieces only (P50/P95 stats and the debugger waterfall already exist): (1) extract `_summarise_turns()` / `_build_timeline()` from `debugger/server.py` into a shared `debug/_turn_timeline.py` and reuse from `bundles show --json` / `inspect` (a per-turn `turns` array with per-stage spans), adding the milestone deltas (VAD endpoint → STT final → agent first token → TTS first byte) computed from existing journal records; tests in `test_bundles.py` and `test_server.py` (guard-ops). (2) Write `docs/latency.md` (flat layout, matching `docs/observability.md`): a table of every latency-adding default with its current value and tuning guidance, guarded by a test asserting each documented value matches the code default; register a "Why was that turn slow?" docs route.

#### L3. "From EasyConfig to Session" graduation guide — *S / M*
**Why.** The quickstart teaches `EasyConfig.mic` + `run`; the teaching ladder hand-rolls pipelines and reaches the production API only at chapter 13. An app builder wanting `subscribe_event`, `send_text`, session actions, or debug bundles has no prose path between the two — `send_text` appears in zero markdown docs today.
**What.** Add `docs/from-easyconfig-to-session.md` (flat `docs/`, no new directory): quickstart → `create_session` + `async with` lifecycle → `subscribe_event` idioms → `send_text` and session actions → `debug='full'` / `export_debug_bundle` / `easycat replay` → the explicit `SessionConfig` escape hatch with a "when you need this" paragraph. Register it in `_DOCS` (audience "app builders") and `docs/README.md`'s map; link from the README's "Advanced" section (which shrinks to one line), teaching ch. 13's intro, and the six scaffold "Next steps" sections. Route resolution and links are then enforced automatically by existing guards.

#### L4. Publish a reference + explanation layer for the production API — *L / H*
**Why.** The mkdocs site publishes *only* the teaching ladder. Event semantics, EasyConfig fields, and Session lifecycle live in docstrings; the architecture explanation (two-layer events, turn FSM, collaborator map) lives in CLAUDE.md — routed to maintainers. Graduating learners have nowhere to go but source.
**What.** Change `docs_dir` to `docs/` (this is real work: prefix all nav paths with `teaching/`, update `edit_uri`, `.mkdocs/hooks.py`, `docs.yml` path filters and strict build, and split nav/site branding into Learn vs Reference). Add `docs/reference/`: an events reference for the ~21 concrete public event types with when-emitted semantics and the provider-scoped vs EasyCat-level distinction; a *handwritten* EasyConfig field reference kept honest by a guard test (the established `public-api.md` ↔ `test_public_api.py` pattern — not mkdocstrings, which isn't a dependency and would render the InitVar aliases and custom `__getattribute__` poorly); a Session lifecycle page (stop/force, postmortem journal reads). Add `docs/architecture.md` carrying the CLAUDE.md prose; CLAUDE.md links to it, shrinking the guarded surface. Add a `diataxis` field to every `easycat docs --json` route with a guard test. Flesh out `create_session`'s one-line docstring. Extend `easycat explain` with concept topics (events, turn-taking, journal) that print a summary plus the docs route.

### Maintain

#### M1. Ratchet the mypy gate beyond `debug/` — *M / M*
**Why.** The typed-wiring decomposition's whole point is type-checked seams, yet the blocking gate covers only `src/easycat/debug`. The ratchet was already sketched in pyproject's mypy-overrides comment, then stalled — and session drifted from 13 to 22 errors, proving advisory-only allows regression.
**What.** Execute the existing plan in feasibility order: runtime (3 errors) and stages (3) first, then session (22, including `_wiring.py` — the seam the gate exists to protect), then integrations (22). Per clean package: add the path to the gate command and the module to the pyproject overrides list. Define the gated-path list once as a justfile variable and have ci.yml run `just typecheck` instead of duplicating it; no mypy.ini (config stays in pyproject). Refresh the stale error counts in the pyproject comment and ci.yml. Transports/validation/cli are the next tranche.

#### M2. Generate the guard command tables from one source — *M / M*
**Why.** Guard command strings live in `cli/_app.py`, the justfile, CONTRIBUTING, CLAUDE.md, and AGENTS.md; adding one guard recipe touches five files plus test expectations. The loud-failure design is right; the copies are not.
**What.** Make the justfile canonical: extract the parsing from `tests/_justfile.py` into a shared helper; add `scripts/regen_guard_commands.py` writing `<!-- BEGIN auto:guard-commands -->` blocks into the three Markdown files (keep the raw `uv run pytest` fallback strings *inside* the generated blocks — agents in no-`just` environments consume them, and generated copies cost nothing) and emitting the `_DOCS_ONBOARDING_*_GUARD_COMMANDS` constants as a generated module imported by `_app.py` (shipped code can't read the repo justfile). Replace the copy-parity assertions with one `--check` staleness test (the regen-teaching pattern); **keep** the functional guards that validate commands actually resolve. Also delete the unreferenced one-time artifacts `ARCHITECTURE_AUDIT.md` and `FIX_REPORT.md`. Expect one edit point per new recipe, not a wholesale collapse of the guard test surface — most of it is functional validation worth keeping.

#### M3. Install-test the extras matrix nightly; broaden live canaries — *M / M*
**Why.** 23 extras are never installed in any CI lane — a renamed SDK symbol or bad version bound ships undetected. Nightly canaries hit only OpenAI despite Deepgram/ElevenLabs/Cartesia secrets being wired in.
**What.** Nightly matrix job: read `[project.optional-dependencies]` via tomllib into a `fromJSON` matrix (new extras auto-covered); each cell does `uv sync --extra <name> --group dev` in a clean env + import-smoke, deriving provider import targets from the existing `required_extra` mapping rather than a parallel list. Handle the known cells explicitly: cartesia is an empty marker extra, funasr-vad is py<3.13, pydantic-ai vs pydantic-ai-v2-beta never co-install, and make a deliberate licensing call on ten-vad. Since the `requires_extra` marker currently marks zero tests, either start applying it or drop the claim and rely on import smoke + offline contract tests with the real SDK present. Extend live canaries: add `--extra deepgram --extra elevenlabs` to that job's sync and run `validate live` across all four providers (non-strict tolerates missing secrets). Record at least one non-OpenAI cassette per transport shape to diversify the 3-cassette, all-OpenAI corpus.

#### M4. Break up the four streaming/bridge hot spots; turn on complexity lint — *L / M*
**Why.** `translate_stream_event` (430 lines, depth 11), `consume_agent_stream` (203), `run_streaming_agent` (~267), and `_transcribe_streaming` (~170) are far outside the codebase norm and sit exactly where future provider/bridge work happens. Nothing in the ruff config stops them growing.
**What.** Refactor behind existing test coverage: the LangChain translator into a per-event-type dispatch table (mirroring the `_PROVIDER_TO_CONFIG` registry pattern); the session streaming/turn-runner pair into named phase helpers; same for the OpenAI STT streamer. Split `runtime/journal.py` (2,056 lines) along its *actual* per-backend seams — keep the Protocol + `JournalView` in place, move InMemoryRingBuffer, the SQL family, the readonly/frozen views, and `run_retention`/`create_journal` into siblings (small blast radius: ~7 import sites; run guard-ops after). Then add C901 + PLR0912/PLR0915 to ruff, enumerating remaining offenders into per-file-ignores so new code cannot regress.

### Extend

#### E1. Single provider-metadata source of truth: extend `ProviderCatalog` — *S–M / H*
**Why.** This is the root cause of the ~15-file in-tree provider recipe. Half the consolidation already exists (`ProviderCatalog` unifies provider/config/env-var; provider reports and the contract matrix already derive from registries with coverage guards). Three fields remain genuinely unsourced and *silent*: doctor's env map, validation's provider markers, and redaction's domain regex.
**What.** Extend the existing `ProviderCatalog` (`_provider_catalog.py`) — do not create a parallel descriptor module — with per-provider `extra` and `api_domains` fields, with the same key-completeness validation it already does for env vars. Derive the three hardcoded consumers from it: `doctor.py:_PROVIDER_ENV`, `runner.py:_provider_marker`, `redaction.py:_SENSITIVE_URL_RE`. Replace scaffold's `_PROVIDER_TO_EXTRA`/`_PROVIDER_TO_ENV_VAR` dicts with catalog lookups; add matrix-row assertions that `required_extra`/`credential_env_var` match the catalog. Add one guard test that every registered provider has all fields populated and doctor's check set equals the catalog. Scope: STT/TTS only — VAD has no credentials and keeps its fallback chain. Update CLAUDE.md's registry bullet to the new truth: registry entry + catalog metadata + config dataclass, and doctor/scaffold/redaction pick it up automatically.

#### E2. Provider-author docs route, custom-transport example, provider package template — *M / H*
**Why.** The genuinely excellent out-of-tree path is invisible: no docs page teaches it, there's no custom-transport example, and the only way to learn server-transport plumbing is importing a private module.
**What.** Write `docs/extending/` pages (one per Protocol: STT, TTS, VAD, Transport, agent bridge) — duck-typed surface, ~30-line complete example, conformance verification — with plain instance injection as the documented baseline (works today, no registry needed); reference the contract kit and entry points only as E3/E4 land. Surface via the *existing* provider-maintainers audience (extend or rename it — don't add an overlapping "extenders" audience). Promote `_AudioQueueMixin` / `_ServerTransportBase` / the TransportDegraded plumbing to a public `easycat.transports` module and add it to `docs/public-api.md` so the public-API guard covers it. Add `examples/custom_transport.py` registered in the examples matrix (guard-examples). Add `easycat init --template provider` generating an external package skeleton (pyproject, Protocol-conforming provider + config, conformance test), smoke-tested by guard-templates.

#### E3. Public text-first eval API; tests + AGENTS.md in every scaffold — *M–L / H*
**Why.** LiveKit's most-praised story is evals shipped inside the starter template. EasyCat can beat it: the journal lets evals assert pipeline facts (interruptions, FSM transitions, TTS scheduling) text-only frameworks can't see. The bundle-eval kit, pytest fixture, judge script, and teaching chapter already exist — what's missing is the live runner and the scaffold payload.
**What.** Extend `easycat.debug.testing` (the established home — no parallel `easycat.testing.evals` namespace): add `run_text_turn(config_or_session, user_input) -> TurnResult` driving one real-bridge turn through the existing send_text path with Noop audio stages, returning a journal-backed result sharing vocabulary with the existing `assert_*` helpers; promote `assert_llm_judge` from the teaching script and add a per-turn latency assertion reusing the validation percentile code. Ship `tests/test_agent.py` (offline, key-free — stub agent or checked-in fixture bundle, never a live LLM) and an AGENTS.md in every scaffold template; extend `test_scaffold_smoke.py` to actually run pytest inside a generated project. Add a "Testing and evals" docs route covering the ladder: bundle fixtures → text turns → teaching ch. 12 metrics → live audio.

#### E4. Entry-point provider discovery; open the closed config unions — *M / M*
**Why.** Registries are private, `STTConfig`/`TTSConfig` are closed unions, and `ProviderCatalog`'s reverse map freezes at import — third-party providers can never get string shortcuts, doctor checks, or scaffold coverage.
**What.** Two layers. Layer 1: public `register_stt_provider(...)` / `register_tts_provider(...)` mutating the catalogs; make the reverse map rebuild (or derive lazily) post-construction, preserving key-parity validation per registration. Layer 2: `easycat.stt_providers` / `easycat.tts_providers` entry-point groups discovered via importlib.metadata at first factory call, feeding Layer 1. The union work is narrower than it looks — runtime dispatch is already catalog-driven, so just convert the few `isinstance(x, STTConfig/TTSConfig)` checks in `config/easy.py`, `_factory.py`, `_tts_alignment.py` to catalog-membership checks. Exclude VAD (no registry exists; building one is a separate prerequisite). Surface discovered providers in `doctor` and scaffold's `available_providers()`; add a guard test registering a fake provider via both layers. Depends on E1's metadata fields.

#### E5. Export the contract-test suite as an installable kit — *M / M*
**Why.** `tests/contracts` is the strongest internal asset but unusable by external provider authors; an importable kit makes the third-party path credible and sets the quality bar for a future community listing.
**What.** Build `src/easycat/testing/` (precedent: `debug/testing.py` already ships testing surface in core) with factory-parametrized, subclassable suites per Protocol (`class TestAcmeSTT(STTProviderContractSuite): provider_factory = ...`), offline by default with an optional live mode. This is generalization, not extraction — today's contract tests assert semantics only against hand-rolled fakes, so promote those assertions into suite methods runnable against any provider. Reuse `validation.redaction` and `provider_capabilities`/`provider_reports` rather than duplicating them. Keep the surface matrix and cassette bookkeeping in-repo, but re-point the four protocol-semantics files at the kit suites so kit and in-tree assertions can't drift. Document in the provider-author guide (E2); extend guard-contracts to cover the kit's own tests.

#### E6. Agent-bridge starter base class and a detection hook — *M / M*
**Why.** A new bridge author faces a 6-method protocol with the existing 1,300–1,600-line bridges as the only templates, and auto-detection requires editing a hardcoded ~9-branch isinstance chain in core.
**What.** Add `integrations/agents/template.py` with a `BridgeTemplate` owning the *remaining* boilerplate (the interruption journal protocol is already factored into `run_interruption_journal_protocol()` — delegate to it): the invoke() cursor lifecycle including the BaseException/`safe_exit_cursor` dance, default `COMMITTABLE_BOUNDARIES`, scrubbed state serialization, safe no-op mutation methods. Authors implement only event streaming, interruption planning, and `snapshot_state`. Refactor `GenericWorkflowBridge` onto it as proof, keeping `test_agent_bridge_contracts.py` green — this matches the blessed STTBase/TTSBase precedent. Add `register_agent_detector(predicate, bridge_factory)` consulted *after* the AgentRunner-unwrap and bridge-passthrough steps but before the framework branches; programmatic registration only for now. Move the `configure_runtime` contract from the `base.py` NOTE comment into prose docs (it can't join the protocol — `@runtime_checkable` would break isinstance). Add the missing top rung ("full bridge via BridgeTemplate") to teaching ch. 14.

## 4. Top 5 first moves

1. **O1 — Fix the install path.** Smallest effort, unblocks everything downstream: no recommendation matters if a scaffolded project can't resolve its dependency. Do it first and alone.
2. **O2 — README restructure.** The single highest-traffic surface; pairs naturally with O1's README touch-ups, and the guard-update muscle it builds pays off in every later doc change.
3. **L1 — Human/machine doc split + llms.txt.** Sweeps every onboarding and learning surface at once, removes the largest readability tax, and turns the guard system from pinning boilerplate into enforcing brevity.
4. **E1 — ProviderCatalog as source of truth.** Small-to-medium effort, kills the most dangerous *silent* failure modes (doctor, redaction, markers), and is the prerequisite for E4's plugin story.
5. **O3 — `easycat console`.** The first move that changes what EasyCat *feels* like: a zero-key first run ending in a journal replay — the field's winning first-60-seconds, with EasyCat's differentiator as the finale.

(L2's latency work and O4's playground are the natural next wave: together they convert the journal from internal strength into the visible moat.)

## 5. Dropped after reality-check

Ideas removed because verification showed the repo already does them — do not re-litigate:

- **P50/P95 per-stage latency stats in `validate latency`** — fully implemented in `validation/latency.py` (stage durations, percentile blocks, budgets) with 47 tests.
- **Waterfall view in the debugger UI** — `debugger/server.py` already renders a per-turn, per-stage waterfall; only the CLI surfacing remains (L2).
- **A new `ProviderDescriptor` module** — `_provider_catalog.py` already unifies provider/config/env-var with completeness validation; extend it, don't duplicate it (E1).
- **Rewriting `provider_reports.py` / the contract matrix to iterate descriptors** — both already derive adapter/env-var from the live registries with coverage guards; remaining fields are intentionally validation-side.
- **Scaffold provider-mapping sync guards** — `test_scaffold_provider_shortcuts_have_install_and_env_mappings` already fails CI on drift; the gap was only the lack of a shared source.
- **Extracting the bridge interruption journal protocol** — `run_interruption_journal_protocol()` already owns the plan→commit→apply→exit sequence; the template's value is the narrower cursor-lifecycle boilerplate (E6).
- **Building a bundle-eval kit and pytest fixture** — `debug/testing.py` and the `easycat_bundle` pytest11 plugin already ship as public, tested API; E3 only adds the live text-turn runner on top.
- **Moving plan/ out of pre-commit hooks** — `.pre-commit-config.yaml` already deliberately excludes `plan/` from codespell/EOF hooks.
- **"Route keyless readers to examples" as new routing** — the examples matrix already has a "No API keys" row; O2 keeps only the direct-link README shortcut.
- **mkdocstrings-generated EasyConfig reference** — not a dependency, and EasyConfig's InitVar aliases plus custom `__getattribute__` would render badly; L4 uses the repo's handwritten-doc-plus-pinning-guard pattern instead.
- **Wiring NoopSTT/NoopTTS for the keyless demo** — they emit nothing by design; `create_text_session` and `scripted_turn_providers()` are the real keyless paths (O3).
- **A new WS-served playground page** — the WebRTC transport already bundles and serves a client with root redirect and smoke tests; O4 upgrades it.
